🌍 Earthquake Symbol Map - Encoding Comparison

Original Encoding

Encoding Channels:

  • longitude/latitude: Position (quantitative)
  • color: depth (quantitative)
  • size: mag (quantitative)

Colors represent earthquake depth, circle sizes represent magnitude.

✅ Simple and clear - original design works well for showing two numeric attributes

Modified Encoding

Encoding Channels:

  • longitude/latitude: Position (quantitative)
  • color: mag (quantitative) ← Changed
  • size: dmin (quantitative) ← Changed
  • shape: locationSource (nominal) ← NEW

Colors show magnitude, sizes show minimum distance, shapes show location source.

⚠️ Shape channel supports limited shapes. Works well with 2-3 categories.

🔍 Why is there a warning about the shape encoding?

The shape channel has important limitations:

  1. Limited shape palette: Only ~8 shapes are typically available
    • circle, square, cross, diamond, triangle-up, triangle-down, triangle-right, triangle-left
  2. Perceptual effectiveness: Shape is less effective than color for distinguishing categories
    • Harder to see differences at small sizes
    • Less intuitive than color
    • Problems for colorblind viewers? No, shapes work universally
    • Better for: 2-3 categories maximum
  3. Scalability issue: If you had MORE unique values in locationSource than available shapes
    • Vega-Lite would recycle shapes (same shape for multiple values)
    • This creates visual ambiguity and confusion
    • A warning might appear about insufficient shapes

✅ In this case: You only have 2 location sources (us, ak), so the shape encoding works fine without issues!

✨ Best Practice: Explicit Shape Scale

To avoid any implicit behavior, define shapes explicitly:

"shape": {
  "field": "locationSource",
  "type": "nominal",
  "scale": {
    "domain": ["us", "ak"],
    "range": ["circle", "cross"]
  }
}
✅ This explicitly maps us→circle and ak→cross, making the encoding predictable and intentional.

💡 When to use shape encoding (and when not to)

✅ Good Use Cases

  • 2-3 categorical values only
  • Shapes are very distinct (circle vs cross)
  • Combined with other channels (color, size)
  • Supporting accessibility (shapes + color)
  • Print-friendly (works without color)

❌ Poor Use Cases

  • Many categories (>5)
  • Very small marks (hard to see shape)
  • Only channel for distinction
  • Similar shapes (triangle-up vs triangle-down)
  • Trying to show ordinal data (shape isn't ordered)
